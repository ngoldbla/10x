# The First Run — welcome, first flick, tip budget (PRD-34 + PRD-18)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or
> superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** one coherent first-run flow on iOS — a welcome ledger that confirms
the $4.99 purchase, then the tutorial's first beat played for real (one empty
cell, one flick, one 7) — plus the TipKit-shaped budget that governs every
in-game hint afterwards, and the deletion of the whole `-uxdemo` prototype rig.

**Architecture:** PRD-34's onboarding half and PRD-18's welcome card are the
same screen sequence, so they ship as one view (`Sources/App/FirstRun.swift`)
driven by two independent flags. `welcome.seen` gates the ledger; the existing
`help.seen` gates the playable beat. That pairing is what makes the update
install behave: a 1.1 player (flag absent, `help.seen` true) gets the ledger
once and no lesson, a fresh install gets both, everyone else gets neither.

The tip budget is a pure `Sources/Shared` module (`TipCoach.swift`) so the cap
is unit-tested rather than eyeballed, with a two-line presenter in the game
screen. The framework is not adopted — see "Deviation" below.

**Tech Stack:** Swift 6 / SwiftUI, CouchKit glass, xcodegen, `swift test` for
the pure modules, `sim-use` + `ax-snapshot.py` for the driven verification.

## Global constraints

- **iOS only.** `TouchHomeView` is the only host. tvOS keeps its `HelpOverlay`
  first run and macOS keeps its menu-driven tutorial (PRD-18 §2).
- **Two cards, then never again.** No third first-run screen, no "what's new"
  on future updates, no rating prompt — ever (PRD-7 covenant).
- **One tap out.** The beat is skippable from its first frame; nothing in the
  flow can trap a player who bought the app to play, not to be taught.
- **Persistence goes in its own blob.** `welcome.seen` and `nine.tips` are new
  top-level `CouchStored` keys, never fields on `LibraryEntry`
  (EXECUTING-A-PRD §2). `TipLedger` decodes tolerantly or the blob dies.
- **Never leak what the screen doesn't show.** The undo tip fires off a wrong
  digit, so it must be gated on `prefs.errorHighlight` exactly like the error
  haptic and the spoken "wrong" (EXECUTING-A-PRD §4).
- **The AX lane is a contract.** New first-run chrome changes `home.txt`, and a
  tip firing mid-capture would make the game screens flaky — seed both new keys
  in `ax-snapshot.py` and re-record deliberately.
- **Copy lives in `Phrase` blocks** (PRD-20's localization seam).

## Deviation, recorded up front

TipKit-the-framework is not adopted. The requirement is a *global* cap — three
tips ever, one per session, across all tips — and TipKit's rules are per-tip
(`MaxDisplayCount`) plus one app-wide `displayFrequency`; the cross-tip budget
has to be hand-held either way. Against that, the framework brings a datastore
on the 800 ms launch path, a card that is not in the glass language without a
custom `TipViewStyle`, and nothing that `swift test` can reach. The cap ships
as ~90 pure lines with tests. Recorded in DEVIATIONS.md.
